# お友達紹介「バディ割」— 設計と運用（正典）

作成: 2026-07-28 / 対象ページ: https://miura-diving.com/buddy/
（このファイルは deploy 対象外。サーバーに上げない）

## 戦略サマリー

現状の新規獲得は Google広告（総予算¥10,000）が主力だが、これは OWD 0.2人分の予算でしかない。
一方で LINE友だち89人と既存受講生という「すでに信頼のある層」は未活用。**紹介は現金コストがほぼゼロの獲得チャネル**であり、広告より先に整備すべき本命。

ダイビングは構造的に紹介と相性がいい:
- バディ潜水が前提で、そもそもひとりで完結しない
- 見込み客の最大の障壁は「怖い・泳げない・ひとりが不安」。これを解くのはLPのコピーではなく、**すでに潜っている友達の一言**
- 紹介者への報酬が「友達と一緒に潜る権利」＝**その人が本当に欲しいもの**。ギフト券より強い

## オファー（2026-08-01 開始）

| 対象 | 特典 | 実額 |
|---|---|---|
| 紹介した認定ダイバー | 付き添いダイビング **¥6,600引き** | ビーチ ¥13,200 → **¥6,600**（半額）／ ボート ¥19,800 → **¥13,200** |
| 受講する友達 | 器材レンタル1日分無料 | **−¥5,500**（OWD・AOW どちらも） |

- 付き添いのタイミングは「友達の講習日に同行」「友達の認定後の初ファンダイブに同行」の**どちらでも可**。
  → 後者は通常のガイド業務で回せるうえ、新規ダイバーの初ファンダイブ（¥13,200）が同時に立つので**紹介特典が新規売上を生む**。
- レンタル器材代（¥5,500/日）は特典対象外。
- 紹介人数の上限なし（1名紹介＝¥6,600引き1回）。
- **同日に使える割引は1回（¥6,600）まで**（2026-07-28 ユーザー決定）。複数紹介ぶんのまとめ使い不可。
  理由: 2人紹介＝−¥13,200でビーチ2ダイブが実質無料、3人なら赤字になるため。
  ただし「使えず消える」だと複数人を紹介する動機が消えるので、**残りは次回以降に繰り越し・有効期限は紹介日から1年**とした（この繰り越し条件はこちらの提案。変更可）。
  副次的な効果として、繰り越しは紹介者の再来店理由になる。
- **値引き額はビーチ・ボートとも¥6,600で統一**（2026-07-28 ユーザー決定）。ボートは乗船料が実費で出るため半額（¥9,900）だと粗利が薄い。ビーチはこの額がちょうど半額になるので、訴求は「¥6,600引き／ビーチなら半額」で通す。

### コース別の総額（特典適用後）

| コース | 通常総額 | 特典後 |
|---|---|---|
| OWD（講習費¥53,900＋レンタル2日¥11,000） | ¥64,900 | ¥59,400 |
| AOW（講習費¥59,800＋レンタル2日¥11,000） | ¥70,800 | ¥65,300 |
| OWD＋AOWセット（セット講習費¥108,700＋レンタル4日¥22,000） | ¥135,700 | ¥119,700 |

**⚠ セットは特典を2回（−¥11,000）適用する。** 1回だけにすると
「別々に取る（¥59,400＋¥65,300＝¥124,700）」＜「セット（¥125,200）」となり、セット割が逆転して破綻する。
2回適用でセット¥119,700 ＝ 別々より¥5,000安い、が保たれる（＝セット割¥5,000ぶん）。

## LPの役割分担（統合ではなく分業）

| 目的 | 置き場所 | index |
|---|---|---|
| 広告クリック → OWD申込 | `lp/owd/`（既存。紹介は料金直後の小ブロックのみ・CTAは変えない） | noindex |
| 紹介する側 → 友達に転送 | **`buddy/`（新規）** | index |
| AOW検討者（＝既存客・LINE友だち） | `license/` ＋ LINE配信 | index |

- **AOW専用の広告LPは作らない。** AOWの見込み客はGoogle検索にいない（既にOWD保有者＝自社の顧客リスト）。¥10,000の予算を分割するのは小予算運用の自殺行為。
- **紹介ページを広告LPと分けた決定的理由**: `.agents/google-ads-plan.md` に「8月末までLP URLは広告専用にすること（SNSに撒くと計測が混ざる）」と定めている。紹介は転送される前提の施策なので、同じURLに載せると計測設計が壊れる。

### HPへの掲載（2026-07-29 実施）

LINE配信はタイムラインを流れて消えるので、**紹介したくなった半年後に思い出せる置き場所**としてHPに常設した。

| 置き場所 | 内容 |
|---|---|
| トップ `index.html` | 「お客様の声」の直後にバナー（FAQの手前）。ヒーロー・料金より下に置く |
| `license/`・`fun-diving/` | 既存のバナー（変更なし） |
| 主要15ページの `footer-nav` | テキストリンク「お友達紹介（バディ割）」を常設 |
| グローバルナビ | **入れない**（既に8項目・新規の第一接点ではない） |
| `trial-diving/` 本文 | **バナーを置かない**（体験ダイビングは特典の対象外・誤解を招く） |

- トップの掲載位置を中盤にした理由: トップの訪問者は大半が新規（体験・ライセンス検討中）。
  ヒーロー直下に割引を出すと「値引きありき」の第一印象になり、少人数・丁寧という本来の訴求と衝突する。
  一方で「友達と2人で来ていい」というメッセージは新規の不安（ひとりが不安）にも効くので、社会的証明（お客様の声）の直後に置いた。
- **計測はHP経由と区別していない**（サイトにGA未導入・合言葉「バディ」＋紹介者名で台帳管理する運用のため）。
  分けたくなったら、HP側のリンクだけ `?from=buddy-hp` にしてフォームの【流入元】行で見分ける。

### 共有ボタンとOGP（2026-07-29 実施）

紹介ページは「転送されること」が成果なので、`buddy/index.html` の「やることは3つだけ」直後に共有ブロックを設置した。

| ボタン | 挙動 |
|---|---|
| LINEでお友達に送る | `https://line.me/R/share?text=...`（定型文＋URLを事前エンコード） |
| リンクをコピー | Clipboard API →（非対応時のみ）`execCommand` フォールバック。結果を `aria-live` で読み上げ |
| 他のアプリで送る | `navigator.share` がある端末のみ表示（Instagram DM・メール等に流せる）。無い環境では `hidden` のまま |

- 定型文: 「ダイビングのライセンス、一緒に取らない？いま紹介だと、ふたりとも特典があるみたい。」
  **紹介者本人が送る前提なので、店側の宣伝文句にしない**（友達に送る一言として自然な文にしてある）。
- OGP画像を `image/og-buddy.jpg`（**1200x630 JPG**）に差し替え。
  以前は hero の `enjoy-surface-duo.webp`（800x534）を流用しており、LINE/Xのカードで中途半端に切れていた。
  元画像から `y=75..495` を切り出して1200x630に拡大（顔とピースサインが枠に収まる位置）。
  `og:image:width/height`・`twitter:card=summary_large_image` も併せて追加。
- 定型文やOGPを変えるときは、**LINEのトーク画面で実際に転送して見え方を確認する**こと。

## リーガル（検品済み・2026-07-28）

- 値引きはすべて**自社サービスの値引き**の形で提供している（現金・金券ではない）。景品規制の論点を避けやすい設計。ただし断定はできないため、規模が大きくなったら専門家に確認する。
- 二重価格表示: 「通常¥64,900」「¥13,200→¥6,600」等はすべてサイト掲載の正価。実態あり。
- 希少性: 「少人数制のため同日にご案内できる人数に限りがあります」は実態どおり。虚偽の限定表示なし。
- ステマ規制: **SNS投稿を特典の条件にしていない**（FAQで明示）。条件化すると #PR 表記義務が発生するので、今後も条件にしない。
- 打消し表示は本文と読めるサイズで併記済み。特商法表記へのリンクあり。

## 決定済み（2026-07-28 ユーザー判断）

1. **セット受講の特典は2回適用**（−¥11,000・総額¥119,700）で確定。
2. **ボートの値引きは−¥6,600**（半額の¥9,900ではない）。訴求は「¥6,600引き／ビーチなら半額」で統一。
3. **講習日への同行は運用上問題なし**。「講習日に同行」「認定後の初ファンダイブに同行」の2択のまま案内してよい。

## LINEの絞り込み配信（送る相手を選ぶ）

**✅ 2026-07-28 に実行済み。** 指定の8名を除いた86人へバディ割告知を配信（消費87通・残24通）。
手順を確立したので、次回からは下の「確立した手順」をなぞるだけでよい。

### 確立した手順（除外したい人が少数のとき）

```
1. chat.line.biz で除外したい人にタグを付ける（タグ名「配信除外」）
2. manager.line.biz → データ管理 > オーディエンス > 作成 → タイプ「チャットタグ」→ そのタグを選択
   （チャットタグ型だけは「50人以上」の制限がない。他のタイプは全部50人以上必要）
3. ステータスが READY になるまで待つ（数分）
4. python3 .agents/line/line_broadcast.py audience list            # audienceGroupId を確認
5. python3 .agents/line/line_broadcast.py narrowcast --date YYYYMMDD \
       --exclude-audience <id> --text "本文"                        # --yes が無ければプレビューのみ
```

現在のオーディエンス: `2352293998572`（配信除外リスト・8人・READY）。
タグ `配信除外` は tagId `agp2smqmyqkkon7biolnnj5bai`。除外メンバーの増減はチャットのタグを付け外しすれば
オーディエンスに自動で反映される（作り直し不要）。

### なぜこの遠回りが必要か（実測でわかったこと）

- **chat.line.biz の userId と Messaging API の userId は別体系**。
  チャット画面から取れた8人のuserIdは、Messaging APIの `GET /v2/bot/profile/{userId}` で**8件とも404**。
  そのため `POST /v2/bot/audienceGroup/upload`（userIdリストからオーディエンス作成）は
  `No valid audience id` で失敗する。**この道は使えない。**
- 一方、**管理画面でチャットタグから作ったオーディエンスは Messaging API 側からも見える**
  （`GET /v2/bot/audienceGroup/list` に出てくる）。だから作成だけUIでやれば、配信はAPIから叩ける。
- `multicast` は「送る人のuserIdリスト」を渡す方式なので、除外リストからは宛先を作れない。
  「全員−数人」をやるなら `narrowcast` + `recipient.not.audience` 一択。
- narrowcast のレスポンスボディは空。requestId は `X-Line-Request-Id` **ヘッダー**で返る。

### 参考: 実測した制約

| 項目 | 結果 |
|---|---|
| アカウント | @438towqp・**未認証** |
| 友だち | 107人・ブロック13人 → **配信可能94人** |
| `GET /v2/bot/followers/ids` | **403**（認証済アカウント限定） |
| 属性で絞り込み（年齢・性別等） | ターゲットリーチ100人以上が必要 → **95人なので不可** |
| チャットタグ型オーディエンス | 人数制限なし → **これだけが使えた** |

### まだ有効な代替手段

- **管理画面のチャットから個別送信**: 数人だけに送るならこれが最短。表示名で選べる。
- **認証済アカウントを申請**（無料・審査あり・2週間程度が目安）:
  料金プランとは別物なので**無料プランのまま取れる**。通ると `followers/ids` が解禁されて
  `roster sync` → `multicast --skip "名前"` が使えるようになるほか、
  LINEアプリ内の検索結果に表示される・青バッジが付く・販促ポスターが作れる。
  **未認証だと検索で見つけてもらえない**ので、集客の観点でも取っておく価値が大きい。

- 除外リスト（氏名・userId）は `~/.config/line/exclude-list.json` と `exclude-list.txt`（git外・600）。
  **リポジトリはpublicなので顧客名・userIdは絶対にコミットしない。**

## 計測

- 月末に予約台帳で「紹介者」列を集計 → 紹介経由の成約数 ÷ 全成約数。
- 見る数字: ①紹介発生数 ②紹介→成約率 ③付き添いダイブの実施率（特典が使われずに終わっていないか）。
- ③が低い場合は「認定後の初ファンダイブ」への誘導が効いていない → LINEで個別に声かけする運用に切り替える。
